## 1. Кратко

Telegram Mini App кинотеатра Nova Cinema: React-фронт внутри Telegram WebApp, FastAPI-бэкенд,
отдельный aiogram-бот, PostgreSQL в проде и SQLite в разработке.

Онлайн-оплаты нет и не будет: пользователь создаёт **заявку**, администратор связывается с ним
и подтверждает бронь вручную через админ-панель.

**Главный принцип проекта:** ничего, что видит зритель, не зашито в код. Фильмы, цена, расписание,
новинки, бонусы, мелодии, контакты, размер зала и правила бронирования живут в базе и меняются
администратором без правки исходников и без обращения к разработчику.

| Показатель | Значение |
|---|---|
| Backend | 2 938 строк Python |
| Frontend | 4 880 строк TS/TSX |
| Тесты | **108 тестов** |
| API | **59 маршрутов** |
| Таблиц в БД | **13** |
| Миграций | 14, head = `0013_settings_bot_username` |
| Словари RU/UZ | по 389 ключей, синхронны |

**Слои бэкенда:** роутер принимает и валидирует → сервис содержит бизнес-правило → модель работает
с БД. Роутеры не лезут во внешние API напрямую, сервисы не знают про HTTP-статусы кроме явных
`HTTPException` в местах, где правило домена совпадает с ответом API.

## 3. Модель данных

| Таблица | Назначение |
|---|---|
| `users` | аккаунт Telegram, роль (`user`/`admin`) |
| `movies` | каталог, i18n-поля RU/UZ, `is_new` + `new_until` |
| `reviews` | отзывы, поле `approved` для модерации |
| `shows` | **расписание — единственный источник правды** |
| `bookings` | заявки, `ticket_price` заморожен, `created_at`, `completed_at` |
| `seat_holds` | временная блокировка мест |
| `favorites` | избранное |
| `user_notifications` | уведомления зрителю |
| `admin_notifications` | уведомления администратору |
| `cinema_settings` | **одна строка (id=1) — весь профиль кинотеатра** |
| `bonuses` | акции и бонусы |
| `melodies` | мелодии, максимум 3 |
| `gallery_images` | фото интерьера/зала/бара |

### Что содержит `cinema_settings`

Название, адрес, телефон, Telegram, Instagram, username бота, ссылка на карту, широта/долгота, часы работы,
описание — всё с UZ-вариантами. Плюс: цена билета, валюта, `hall_rows` × `hall_cols`,
`max_seats_per_booking`, `hold_minutes`, `booking_days_ahead`.

### Жизненный цикл брони

```
pending ──► contacting ──► confirmed ──► watched
   └────────────┴─────────────┴──► cancelled
```

- Отмена освобождает места, **все остальные статусы их держат**.
- QR действителен для `confirmed` и `watched`.
- Отзыв доступен только при статусе `watched`.

  админом действует только вперёд.
- **Статусы**: добавлены `contacting` и `watched`, `completed` мигрирован в `watched`,

- **Зал**: геометрия переехала в настройки. Структурно устранён баг, где `seats_count` по умолчанию
  был 80 в БД против 15 в API — количество мест больше не хранится на сеансе.
- **Новинки, бонусы, мелодии, галерея**: модели, CRUD и публичные эндпоинты.
- **`Booking.created_at`** — колонки не было, а ТЗ 4.8 требует «время создания».
- Из этапа 9 перенесён **выбор сеанса**: экран времени больше не просит ввести время вручную,
  а показывает реальный список из расписания; окно дат берётся из `booking_days_ahead`.

**Миграция `0012`** проверена на живой БД в обе стороны: `session_prices` копируется 1:1, времена из
`sessions_json` разворачиваются на 14 дней вперёд, `completed` → `watched`, `ticket_price`
восстанавливается из `total`. Downgrade возвращает `session_prices` из `shows`.

**Попутно починен предсуществующий блокер:** миграция `0010` использовала Postgres-only
`ALTER COLUMN ... TYPE BIGINT` и роняла всю цепочку на SQLite — локальная разработка и тесты
миграций были невозможны. Добавлена проверка диалекта, на Postgres поведение не изменилось.

### Этап 5 — Telegram Mini App: основной интерфейс ✅

Главная страница собрана из всех элементов, которые перечисляет ТЗ.

| Элемент | Состояние |
|---|---|
| Каталог | был; вынесен в переиспользуемый `MovieCard` с бейджем «Новинка» |

**Фильтр по дате.** `GET /api/movies` получил параметр `date`: каталог сужается до фильмов
с активным сеансом в этот день, а `sessions` содержит времена только этого дня. Раньше поле
объединяло времена всех дат.

**Нижняя навигация.** В CSS с самого начала было зарезервировано `padding-bottom: 94px` под таб-бар,
которого не существовало — место просто пустовало. Теперь там навигация, а дублирующая ссылка
на профиль из шапки убрана.

**Валюта перестала быть захардкоженной.** С этапа 3 админ может её менять, но `formatMoney`
всё ещё брал значение из словаря. Добавлен `setCurrency()`: значение приходит из
`GET /api/settings` и из ответа эндпоинта мест, словарь остался фолбэком.

**Узбекские даты.** Chrome не имеет коротких названий месяцев для латинского узбекского —
`Intl` выдавал «M08 22, Sat». Названия прописаны явно, теперь «Shan, 22 Avg».

**Демо-сид получил UZ-поля.** Фильмы из админки переводятся автоматически, а сид заполнял только
русские колонки, поэтому в UZ-режиме каталог оставался русским и проверить двуязычность на демо-данных
было нельзя.

**Проверено в браузере** на мобильном вьюпорте 375×812: обе страницы, переключение RU/UZ с сохранением
после перезагрузки, фильтр по датам, лента новинок, нижняя навигация. Ошибок в консоли нет.

### Этап 6 — каталог и карточки фильмов ✅

Карточка получила два недостающих элемента из перечня ТЗ; остальное было с прошлых этапов.

**Доступные сеансы в карточке.** `GET /api/movies/{id}` отдаёт новое поле `schedule` —
сеансы, сгруппированные по датам. Прошедшие дни отбрасываются, окно совпадает с
`booking_days_ahead`, неактивные сеансы не показываются: карточка не может предложить слот,
который нельзя забронировать. Тап по времени ведёт сразу в зал, минуя выбор даты и времени.

**Кнопка «Поделиться».** Формирует Telegram-ссылку `t.me/<bot>?startapp=movie_<id>`.
Username бота добавлен в настройки кинотеатра (миграция `0013`) — админ задаёт его сам,
в публичном ответе `@` срезается. Внутри Telegram открывается системный диалог «Поделиться»,
вне Telegram ссылка копируется в буфер. Приём такой ссылки и обработка битых/устаревших —
этап 8.

**Проверено в браузере:** расписание на 7 дней с переходом в зал по тапу, кнопка выдаёт
корректную ссылку, зал открывается (3 ряда, 15 мест), ошибок в консоли нет.
Миграция `0013` прогнана вверх и вниз.

### Этап 7 — новинки и поиск ✅

**Поиск расширен** с одного названия до всех данных карточки: название и его часть, жанр,
описание, страна, режиссёр, актёры и год. `GET /api/movies` получил параметр `q`.

Сопоставление выполняется в Python, а не в SQL, и это осознанно: `LIKE` и `lower()` в SQLite
сворачивают регистр только для ASCII, поэтому «дюна» не нашла бы «Дюна» на локальной базе,
хотя на PostgreSQL всё работало бы. Каталог одного зала невелик, цена такого решения — ноль.

**Новинки стали фильтром.** Параметр `only_new` и одноимённый чип на главной. Раньше новинки
были только лентой; теперь по ним можно отфильтровать каталог. Флаг учитывает `new_until`,
то есть истёкшие новинки в выдачу не попадают.

**Поиск ушёл на сервер** с дебаунсом 300 мс, жанр остался клиентской фасеткой поверх
результата. Пустая выдача показывает «Ничего не найдено» и кнопку сброса всех фильтров.

**Найден и исправлен баг с актёрским составом.** `localized_movie_text` брал
`cast_json_ru or cast_json`, но дефолт локализованных колонок — строка `"[]"`, которая
истинна. Из-за этого у всех фильмов, созданных не через админскую форму (демо-сид, прямой
insert, импорт), поле «В ролях» на карточке было пустым — что и было видно на этапе 6,
но я тогда прошёл мимо. Добавлен `_cast()` с проверкой на пустой список и регрессионный тест.

### Этап 8 — «Поделиться» и deep links ✅

**Реализовано вне этой сессии** (Codex), проверено и дополнено здесь.

- `backend/services/deep_link.py` — единый формат payload `movie_<id>`, чтобы кнопка,
  бот и Mini App не разъехались.
- Бот: `CommandStart(deep_link=True)` обрабатывает `t.me/<bot>?start=movie_<id>` и отвечает

  показывает «Фильм недоступен» вместо сырого текста.
- `share_link` отдаётся прямо в `GET /api/movies/{id}`.
- 30 тестов в `test_deep_links.py`: удалённый фильм, снятый с публикации, несуществующий,

**Сделано в этой сессии:**

- **Контакты бота переведены на настройки.** Раздел «О кинотеатре» держал адрес, телефон

## 5. Ключевые технические решения

| Решение | Причина |
|---|---|
| `app.py` оставлен шимом, а не удалён | не ломать `uvicorn app:app`, Dockerfile CMD и launch.json |
| Одна таблица `shows` вместо `sessions_json` + `session_prices` | два источника правды делали расписание неуправляемым |
| Типизированные колонки настроек вместо key-value | валидация Pydantic 1:1 с формой админки |
| `Booking.ticket_price` отдельно от `total` | цена не должна переписывать историю задним числом (ТЗ 4.5) |
| Размер зала в настройках, а не на сеансе | зал один; на сеансе он порождал рассинхрон 80 против 15 |
| `ShowIn` принимает `session` как алиас `start_time` | админка этапа 2 ещё шлёт старое имя; алиас уйдёт в этапе 4 |
| Лимит мелодий проверяется в сервисе, а не в БД | понятная ошибка 409 вместо нарушения ограничения |
| `DEFAULT_*` только засевают строку настроек | после первого запуска авторитетна БД, не окружение |
| Мажорные апгрейды (React 19, Vite 8, Tailwind 4) отложены | риск не окупается в рамках этого ТЗ |
| Тесты на SQLite, прод на PostgreSQL | быстрый прогон без инфраструктуры; миграции проверяются на обоих |
| Новинки — отдельная вкладка, а не только флаг в форме фильма | ТЗ 4.3 требует управления статусом как отдельной задачей |
| Цена — отдельная вкладка | ТЗ 4.5 требует видеть цену, валюту и статус в одном месте |
| Мелодии ограничены и на сервере, и в UI | сервер даёт 409, интерфейс не показывает форму на четвёртой |
| Валюта через `setCurrency()`, а не через параметр `formatMoney` | не пришлось трогать десятки мест вызова |
| Узбекские месяцы прописаны вручную | `Intl` для `uz-Latn` в Chrome не даёт коротких форм |
| Фильтр по дате — параметр API, а не фильтрация на клиенте | клиент не знает, в какие дни идёт фильм |
| Username бота — поле настроек, а не переменная окружения | ссылку для шаринга меняет админ, а не деплой |
| `schedule` отдельно от `sessions` | плоский список времён нужен каталогу, сгруппированный — карточке |
| Поиск сопоставляется в Python, а не в SQL | SQLite не сворачивает регистр кириллицы, каталог мал |
| Поиск на сервере, жанр — на клиенте | поиск покрыт тестами, жанр мгновенно фильтрует уже полученное |
| Формат deep-link payload — один модуль на бэкенде | кнопка, бот и Mini App читают один контракт |
| Тестовая БД — файл на процесс | общий файл ломал параллельные прогоны |

## 6. Переменные окружения

Секреты и инфраструктура — только здесь. Данные кинотеатра сюда **не** попадают.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | токен бота от BotFather |
| `WEBAPP_URL` | да | публичный HTTPS-адрес Mini App |
| `JWT_SECRET` | да | подпись JWT |
| `ADMIN_TELEGRAM_IDS` | да | Telegram ID администраторов через запятую |
| `DATABASE_URL` | нет | пусто → SQLite `nova-dev.db` |
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | для Docker | параметры БД в compose |
| `CORS_ORIGINS` | нет | список origin через запятую, хвостовой слэш срезается |
| `TELEGRAM_AUTH_MAX_AGE_SECONDS` | нет | возраст initData, по умолчанию 86400 |
| `UPLOAD_DIR` | нет | каталог загрузок, по умолчанию `uploads` |
| `AUTO_CREATE_SCHEMA` | нет | `true` создаёт схему и сидит демо-данные в обход миграций |
| `TMDB_API_KEY` | нет | автозаполнение карточки фильма |
| `OMDB_API_KEY` | нет | рейтинг IMDb при автозаполнении |
| `TRANSLATION_API_URL` | нет | перевод RU↔UZ, по умолчанию публичный LibreTranslate |

**Требует внимания:** `CORS_ORIGINS` сейчас указывает на временный cloudflare-туннель.
Постоянный HTTPS-домен ещё не выдан — до этого адрес придётся править при каждом запуске.

## 9. Открытые вопросы

| Вопрос | Статус |
|---|---|
| Постоянный HTTPS-домен | ожидается, до этого `CORS_ORIGINS`/`WEBAPP_URL` правятся вручную |
| Фото интерьера, зала и бара для галереи | ожидаются, до этого плейсхолдеры |
| Username бота Nova Cinema | нужно указать в админке (Кинотеатр → Username бота), иначе «Поделиться» не построит ссылку |
| Промокоды из удалённой legacy-БД | сохранены: `NOVA10` 10%, `WELCOME` 15%, `NOVASINEMA` 5% — можно завести бонусами в этапе 4 |
